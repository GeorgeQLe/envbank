# EnvBank v0.2.0 feature release ship manifest

## User goal

Publish the bundle and Railway capabilities currently available only on
`main` as a downloadable EnvBank release, then install the verified macOS
binary locally before beginning the SiftCut manifest work.

## Changed files and purpose

- `.github/workflows/release.yml` — advance the immutable tag-only workflow to
  v0.2.0, publish the `v0.2.0` and `0.2` image tags, and build macOS archives
  with cgo plus an explicit `Security.framework` linkage assertion.
- `.github/release-notes-v0.2.0.md` — describe the manifest, bundle, rollout,
  Railway, supply-chain, and alpha limitation boundaries.
- `.gitleaks.toml` and `scripts/test-gitleaks-config.sh` — use the global
  allowlist syntax supported by pinned Gitleaks 8.24.3, retain only narrow
  public extension-key and symbolic HMAC matches, and exercise full Git history
  before proving a synthetic secret is still detected.
- `CHANGELOG.md`, `README.md`, and `cmd/envbank/main_test.go` — advance the
  public feature/version surface and installation examples to v0.2.0 while
  preserving the immutable v0.1.x releases.
- `scripts/verify-release-anonymous.sh` — advance the exact eight-asset,
  provenance, archive, binary, OCI, and health verifier to v0.2.0 and require
  Security-framework linkage on a macOS host.
- `tasks/todo.md`, `tasks/history.md`, and this manifest — record preparation,
  evidence, residual risk, and the post-merge publication boundary.

## User-goal mapping

The new release archives contain the complete `main` implementation through
Railway apply/resume/verify. The macOS archives now include the cgo Keychain
path required by Railway token storage instead of silently compiling the
unsupported stub. Release publication remains fail-closed: only one annotated
v0.2.0 tag whose peeled commit is on protected `main` can trigger it, and an
existing release is never overwritten.

## Adversarial review

The release diff was checked for mutable-tag behavior, release overwrites,
credential exposure, incorrect asset/version names, stale image channels,
archive traversal, missing provenance subjects, unsupported platform claims,
and accidental deployment behavior. Review found that the old release matrix
forced `CGO_ENABLED=0` on macOS, which would expose Railway commands while
compiling the Keychain stub they cannot use. The matrix now enables cgo only on
macOS and refuses publication if the binary does not link Apple's Security
framework.

The scheduled Security failure was traced to two known non-secret findings in
the initial commit and incompatible plural global-allowlist syntax. The fix was
validated with the exact action-installed Gitleaks 8.24.3 binary and a newer
local scanner. The synthetic credential remains detectable.

## Residual risk

The macOS binaries remain unsigned and unnotarized. Railway cannot verify remote
variable presence without reading values, so verification remains explicitly
limited to immutable identity plus local committed-write evidence.

## Rollback note

Before tagging, revert the release-preparation merge. After tagging, preserve
v0.2.0 and publish a new corrective version; never rewrite its tag, release,
assets, provenance bundles, or image tag.
